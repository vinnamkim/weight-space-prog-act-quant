Sparks of Weight-Space Programming Jump to Activation Quantization

Vinnam Kim (vinnamkim@kaist.ac.kr) · Junhan Kim (junhankim@islab.snu.ac.kr)

Recently, Sparks of Weight-Space Programming (Takehi et al., 2026) showed that an LLM can read and edit another model's weights to fix its behavior. Furthermore, Can a Linear Program Do Weight-Space Programming? (Barry, 2026) extended the idea and showed that the LLM's edit can be found by a linear program over the weights instead. The problem they solved was repetition in Qwen3.5-0.8B text generation. That repetition comes from a specific activation direction that appears during generation and steers the activations into a small region where the repeated tokens reside. This observation made us wonder whether weight-space programming could also resolve the outlier problem in integer activation quantization. It is a natural question, since, as mentioned above, the culprit is again a large activation magnitude along a specific direction similar to the one inducing the loop. Thus, we let Claude Fable 5.2 solve this problem, giving it the context from the previous posts.

In short. On Qwen3-0.6B, Fable 5.2 found the few neurons that write the outlier and edited the weights in closed form, with no training. The largest activation range drops from 7,378 to 772, and 12-bit activations work without any prefix (perplexity 2,991 → 27.7). The same procedure works on five of the six models with this circuit. At 10 bits and below, PrefixQuant is still better on Qwen3 (section 5).

1. Two Errors in Static Integer Quantization

Before going to how Fable 5.2 solves this problem, let us introduce the two types of error in static integer quantization. Static integer quantization itself is widely used on mobile NPUs because it lets the matrix multiplications run on energy-efficient integer arithmetic. It converts weight and activation tensors into integers. This conversion introduces two types of error: 1) clipping error and 2) rounding error.

Unlike the floating-point domain, which can represent [−∞,∞] (even though its representation is actually finite), the integer domain can only represent [Qmin,Qmax], which has finite bounds. Thus, any value outside these bounds is clipped. We call this the clipping error. On the other hand, the rounding error is the gap between a value inside the range and the integer level it is snapped to. For a real range [xmin,xmax] and a b-bit integer range (Qmax−Qmin=2b−1), quantization computes

s=xmax−xminQmax−Qmin,z=Qmin−⌊xmins⌉
x^=s(clamp(⌊xs⌉+z,Qmin,Qmax)−z)

where s is the step size (the interval between two levels), z is the zero point and ⌊·⌉ is round-to-nearest. The error x−x^ splits into the two cases of Figure 2:

x−x^={x−s⌊x/s⌉∈[−s2,s2]xmin≤x≤xmax(rounding)x−xmax or x−xminotherwise(clipping)

The rounding error is bounded by half a step, s/2, so it grows in proportion to the range. The clipping error has no bound. It grows with how far the value lies outside the range.

For a given bit width, the rounding error gets more severe as the interval gets larger. On the other hand, the clipping error can be mitigated by enlarging the interval. This trade-off is why static integer quantization, especially of activations, works best when the values stay within a small magnitude range.

2. Outliers in LLMs

However, modern LLMs such as Qwen3 (Yang et al., 2025) give quantization practitioners a hard time with activation outliers of very large magnitude.

Across every Linear input and output and the residual stream, the largest value is 7,378, and it always comes from the first position in the sequence (position 0). It does not matter which token is there: feeding each of the 150k vocabulary entries as a single-token sequence, all but 10 of them produced a vector with norm between 5,200 and 8,200. These values are known as massive activations, a term from Massive Activations (Sun et al., 2024), which reports them in many LLMs. For quantization they are the worst case of Figure 3: if almost every value sits within ±13 but a single one is 7,300, the 8-bit step becomes 57 and every ordinary value rounds to 0.

PrefixQuant (Chen et al., 2024) systematically shows that these activation outliers usually occur at the first few tokens of a sequence. It separates two kinds of outliers. Channel-wise outliers sit in the same few channels for every token, and rotations, such as the Hadamard transform in QuaRot (Ashkboos et al., 2024) and the learned rotations in SpinQuant (Liu et al., 2024), spread them across channels. Token-wise outliers are confined to a handful of tokens, and rotation shrinks them but does not remove them. PrefixQuant measures the token-wise kind at each down_proj input as the ratio between the largest per-token maximum and the median one. In Llama-2-7B this ratio is 4,161, and still 461 after a Hadamard rotation.

Its fix follows from where the outlier appears. In the models we test, whatever token comes first absorbs the outlier, so PrefixQuant puts a few selected tokens in front of every input (its selection procedure picks <|im_end|> for Qwen3), computes their keys and values once offline in full precision, and stores them in the KV cache. The actual input then starts at position 1. The sink is already in the cache, so none of the tokens that are quantized has to carry the outlier, and the range only needs to cover ordinary values.

3. Erasing an Outlier by Weight-space Programming

Finding the culprit: writers, readers and erasers

Fable 5.2 traced the outlier to a small circuit with three roles (Figure 6). The rest of the post edits each role separately.

① Writers: 6 neurons in layer 2. The huge value enters the residual stream in the MLP of layer 2. This MLP has 3,072 hidden neurons. Neuron j computes one scalar, hj=SiLU(gatej·x)×(upj·x), and adds hj times column j of down_proj (a 1,024-dim vector) to the residual stream. Exactly six neurons (indices 55, 128, 1489, 321, 46 and 646, not residual channels) reach hj=±700 to ±3400 at position 0 and stay below 1 everywhere else. Their down_proj columns all point in nearly the same direction, almost entirely along residual channel 35, so together they write a vector of norm about 6,764.

② Readers: every attention and MLP from layer 3 to layer 27. The vector travels almost unchanged through the middle of the model. Every layer reads the residual through RMSNorm (Zhang and Sennrich, 2019) (50 sites, two norms in each of 25 layers), so all of them see only its direction.

③ Erasers: 15 neurons in layers 26–27. These neurons also fire only at position 0. They write in the opposite direction and erase the vector before the output.

Why would a model build this? Every layer applies RMSNorm before reading the residual, which rescales it to unit size. Once a huge vector has been added at position 0, the normalized result is nearly the same constant vector no matter which token was there. Other tokens send their attention to this "always the same" position when they have nothing better to attend to. Such a position is called an attention sink, a name from StreamingLLM (Xiao et al., 2023).

The circuit that some neurons fire only at position 0 is not specific to Qwen3 either. Sun et al. find such values at the starting token (and in some models at delimiter tokens) in LLaMA2, LLaMA3, Mixtral, Mistral, Phi-2 and others: they appear abruptly after one early layer, stay nearly constant regardless of the input, and fade in the last layers. The Super Weight (Yu et al., 2024) traces them to a few weights in the down_proj of an early layer in Llama, Mistral, OLMo and Phi-3; removing a single one of them makes perplexity rise by several orders of magnitude.

Some notation for the rest of the post. Let x be the residual vector at one position (1,024 numbers). A layer writes by adding columns of its output matrix to x, as the six writers do with their down_proj columns. A layer reads by first applying RMSNorm(x)=γ⊙x/rms(x), where γ is the RMSNorm weight (gain), and then multiplying by an input matrix W. At position 0, after layer 2, the residual is

x0=Mu+r

where u is a unit vector almost entirely in channel 35, M≈6,764, and r is everything else.

Here u is the direction of the outlier: the vector that layer 2 writes at position 0, averaged over several sentences and scaled to length 1. It is not exactly a one-hot vector, but it is very close to one.

About 98.6% of the energy (0.9932) is in channel 35. It is fine to think of u as "1 in channel 35 and 0 elsewhere". The code uses the measured u and does not assume that.

The remainder r is everything at position 0 that is not the writers' push along u: the token embedding, what layers 0–1 wrote, layer 2's attention output and its other MLP neurons, plus the small part of the writers' output that is not along u. Its norm is about 61, roughly 1% of M. Most of r is the same whatever token comes first. The part that changes with the token, which we call the token-specific part, has a norm of about 19, only 0.3% of x0.

First attempt: just shrink it → fails

The easiest edit is to scale the output of the six writer neurons by α, so the vector they write becomes α times as long. It did not work. Perplexity rises from 26.94 to 29.3 at α=0.1, 40.4 at α=0.05 and 684 at α=0.01.

Shrinking the writers scales Mu but leaves the token-specific part of r (norm about 19) as it is. As α decreases, this part is no longer negligible, so position 0 loses the consistent direction it had after RMSNorm. This in turn affects the other tokens.

Change of plan: spread it, don't shrink it

At this point Fable 5.2 went back to what quantization really cares about. The range is set by the largest value in any single channel, not by the norm of the vector. Those are two different things, and the model only needs one of them.

Imagine an arrow of length L lying flat along one axis of a 2D plane. Its largest coordinate is L. Turn the arrow to the diagonal of a square without changing its length, and its largest coordinate becomes L/2. The arrow is as long as before, but the box that contains it is smaller. With 1,024 axes instead of two, the diagonal brings the largest coordinate down to L/1024=L/32.

This idea resembles what the quantization community already calls rotation. Fable 5.2's approach to apply rotation to weights, however, is closer to the weight-space programming. Surprisingly, it also needs none of the architectural changes that rotation methods such as SpinQuant make to allow fusion. The RMSNorm weights (γ) stay where they are, and the embedding stays tied to lm_head (section 5 compares the two). Fable 5.2 calls this Sink Spreading. Right now a norm of 6,764 sits in channel 35 alone, so the maximum is 6,700. Spread along the diagonal, each channel holds about 211 and the norm is the same.

Method: how Sink Spreading works

Overview

Figure 9 gives the whole idea. The rest of this section derives each part and can be skipped on a first read.

Sink Spreading follows the circuit of Figure 6 and changes each of its three roles. The writers in layer 2 are moved so that they write along a new direction u′ instead of u. The readers in layers 3–27 are changed so that they respond to the new sink input v′ as they did to the old one v (exactly, for the average input), while ordinary tokens, which pass through the same matrices, are disturbed as little as possible. The erasers in layers 26–27 are both: they read like the readers and write like the writers, so they get both edits. Nothing else written to the residual stream is meant to change, and every edit is a closed-form rank-one update, with no gradients.

1. Writers: from u to u′

From u to u′. Choose a new unit vector u′ whose entries are all +1/32 or −1/32 (about 0.031) to spread M across dimensions. Thus, the largest entry of Mu is 6,714 and the largest entry of Mu′ is 211.

The map R. The writers' columns in layer 2's down_proj are moved with

R=I+(u′−u)u⊤

Since u⊤u=1, Ru=u+(u′−u)=u′. In general R takes whatever amount of u a vector contains and moves that amount to u′.

R-mapped columns. R can be applied to some weight columns only because left multiplication acts on each column separately, W′=[w1,…,Rwj,…], where column wj is one of the selected columns which are associated with u in the output: the 6 writers in layer 2 down_proj. Decompose wj into two parts:

wj=cju+wj⟂,cj:=u⊤wj,wj⟂:=wj−cju,Rwj=cju′+wj⟂.

What the selected neurons add to the residual is their columns weighted by their activations, ∑jhjwj (sums here run over the selected neurons). Substituting the split:

∑jhjwj=(∑jhjcj)u+∑jhjwj⟂⟶∑jhjRwj=(∑jhjcj)u′+∑jhjwj⟂

The coefficient ∑jhjcj and the orthogonal vector ∑jhjwj⟂ are the same before and after. Only the vector u is changed to u′. How much actually moves is set by that coefficient, and it depends on the token through hj. At position 0 the writers fire hard (|hj| up to 3,400), so the coefficient is huge, about M≈6,764, and Mu becomes Mu′. On ordinary tokens the same neurons are nearly silent (|hj|<1), so the coefficient is tiny by comparison and nothing visible changes.

At position 0 the residual therefore goes from x0=Mu+r to

x0′=Mu′+r

with the same remainder r.

What if R were applied to every column? Ordinary tokens would break. They also use the u direction (channel 35) to carry their own information. Applying R to other neurons except the selected neurons would move that information to u′, smearing it over all 1,024 channels. On the other hand, the selected neurons are safe to edit because they are silent on ordinary tokens, so editing them changes position 0 only. The choice of columns decides when something moves (only at position 0), and R decides where it goes (from u to u′).

2. Readers: from v′ back to v

Now the readers in layers 3–27 receive x0′ instead of x0 at position 0, so what they see after RMSNorm changes too:

v≈32γ⊙u(before),v′≈32γ⊙u′(after)

These approximations drop r. In x0 and x0′, r has a very small norm against M, about 1%, so it barely changes the result. RMSNorm rescales its input to rms 1, that is, to length 1024=32, so the unit vectors come out multiplied by 32.

Every reader therefore has to be fixed so that it treats v′ the way it treated v. The catch is that a reader's input matrix W is shared by all tokens: unlike the writers, it has no part that ordinary tokens leave untouched, and there is no branch or hook at run time. So the question is how one fixed matrix can change only position 0. Its replacement W′ has to meet two conditions at once, where x is an ordinary token's normalized input:

W′v′=Wv(position 0: exact, for the average v′)
W′x≈Wx(ordinary tokens: as close as possible)

The first is a constraint and the second is the objective.

The form of the answer: a correction gated by a score. Take W′=WS with a rank-one S:

S=I+(v−v′)d⊤⟹W′x=Wx+W(v−v′)(d⊤x)

Every input receives the same correction v−v′, but only in proportion to the score d⊤x. One vector d decides, for each token, how much of the correction it gets, so both conditions become conditions on this score.

Position 0, the constraint: score 1. With d⊤v′=1, Sv′=v′+(v−v′)=v, so W′v′=Wv holds exactly.

Ordinary tokens, the objective: score near 0. W′x≈Wx needs d⊤x to be small. With H=𝔼[xx⊤] over ordinary inputs, its mean square is d⊤Hd:

mindd⊤Hdsubject tod⊤v′=1⟹d=H−1v′v′⊤H−1v′

H−1 gives little weight to directions ordinary tokens use a lot and more weight to directions they rarely use, so d recognizes v′ through directions that ordinary tokens leave nearly empty.

So each reader edit is a constrained least-squares problem with a closed-form answer. In practice, the score is 1 on v′ and 0.007 to 0.011 (rms) on ordinary tokens, about 100 times smaller. Fable 5.2 might come up with this update rule from its vast training corpus. It has the same form as the knowledge-editing method ROME (Meng et al., 2022).

3. Erasers: read like a reader, write like a writer

The 15 erasers in layers 26–27 are the last stop of the circuit. They fire only at position 0 and write about −Mu, which brings the residual back to an ordinary size before the final RMSNorm and lm_head. They are readers and writers at the same time, so they need both edits.

Input side: S. An eraser decides when to fire by reading the normalized residual through its gate_proj and up_proj, like any other reader. Layers 26–27 get the S, so the erasers see v′ as v and still fire at position 0.

Output side: R. If their down_proj columns were left alone, they would keep writing −Mu while the stream now holds Mu′:

x0′−Mu=Mu′+r−Mu≠r

The vector of norm 6,764 would never be erased, and a new −6,700 would appear in channel 35. An eraser column is roughly cju with cj<0, so the same R turns it into cju′, and the erasers now remove exactly what the writers put in:

x0′−Mu′=Mu′+r−Mu′=r

For the writers R moves the push. For the erasers it moves the pull.

Correction. The erasers need one more correction. Some of the neurons in layers 26–27 that take part in erasing also fire on ordinary tokens (their |hj| is large there too). To avoid disturbing ordinary tokens, Fable 5.2 does not apply R to these neurons. They therefore keep erasing along u while the stream holds u′, so the final residual at position 0 ends up slightly off, and that changes the prediction made at position 0. Fable 5.2 measured this error as an average and added it to the down_proj columns of the neurons in layer 27 that fire only at position 0. These neurons are silent on ordinary tokens, so the correction reaches position 0 only.

Putting it together

The three edits are applied in order, with no training. First the writers get R. Then the readers are fixed layer by layer from 3 to 27, attention norm before MLP norm. Fixing one layer slightly changes what it writes at position 0, so v′ is measured again before each step. Last, the erasers get R and the correction. Each norm has one S, shared by q/k/v_proj or by gate/up_proj, which makes 50 reader sites in 25 layers.

4. Results

Firstly, we asked Fable 5.2 to check Sink Spreading with activation quantization and weights stay in float on Qwen3-0.6B. The input and output of every Linear layer and every block output (about 400 sites) are quantized with min-max calibration on wikitext-2. The baseline is PrefixQuant.1 Perplexities from here on include the prediction of the first token in each window, so the original Qwen3-0.6B scores 27.38 instead of the 26.94 used in the shrinking experiment above.

Qwen3-0.6B

Without any prefix, 12-bit quantization now works (2,991 → 27.7, against 27.38 in float), and 10 bits reaches 29.4. The largest range drops from 7,378 to 772. 8 bits still fails, where the prefix holds at 36.1.

Three extra steps for quantization

Even though Sink Spreading fixes the outlier in the residual stream, Fable 5.2 used three more steps to make quantization easier. The first two leave the function unchanged: the first moves magnitude from activations into weights as in SmoothQuant (Xiao et al., 2022), and the second uses the fact that RMSNorm ignores the scale of its input. The third costs about 0.02 perplexity. The first two are used in both edited models; the third only in "Sink Spreading + M × 0.3".

Rebalancing hidden values. At position 0 the writer and eraser neurons still produce hj of up to 3,400 at the down_proj input. Row j of up_proj is divided by cj and column j of down_proj multiplied by cj, with cj chosen so that the position-0 value becomes half the largest hj of ordinary tokens.

Shrinking the final residual. The correction for the erasers (see "Erasers" above) adds a vector at position 0 only, through layer-27 neurons that fire only there. The same correction can also shrink the residual entering the final RMSNorm. RMSNorm ignores the scale of its input, so Fable 5.2 aims the correction at 0.2 times the original position-0 residual, in the same direction, instead of the original itself. The output does not change, and an outlier of 1,907 at that quantization site disappears.

Scaling M by 0.3. Even after spreading, M can also be reduced further with the direction u′ unchanged. Fable 5.2 searched for the scale and chose 0.3M. This is done by multiplying the writers' up_proj rows by 0.3, which scales their hj and so M. In each layer Fable 5.2 reprograms its least-used MLP neuron to fire only at position 0 and scale that layer's own writes at position 0 by 0.3 as well, so the direction stays the same. The position-0 peak falls to 131, below ordinary tokens, and 10-bit perplexity improves from 44.4 to 29.4.

5. Conclusion and comparison with existing solutions

This post showed that weight-space programming with Fable 5.2 applies to activation quantization. Reading only the weights, it found the circuit behind the massive activation and removed the outlier with closed-form weight edits and no training, and the same procedure makes 12-bit activations work on five of the six models that have this circuit. Unlike PrefixQuant, it needs no prefix KV cache or runtime change, and unlike rotation, it keeps the checkpoint format, including the tied embedding and lm_head. In accuracy, however, it still falls short of the existing solutions: it fails at 8 bits, and at 10 bits it trails PrefixQuant on Qwen3.

PrefixQuant
keeps the outlier token in a prefix at high precision
Pros
  • model weights unchanged, function preserved
  • strong even at 8 bits (A8 PPL 36.1)
Cons
  • the prefix KV cache must be stored and the runtime changed to use it
  • a poorly chosen prefix token hurts accuracy
  • misses outliers in mid-text (Llama-3.2-1B-Instruct, A10 PPL 18,256)
Rotation (SpinQuant, QuaRot)
rotates the whole space to flatten every channel
Pros
  • orthogonal, so the function is preserved exactly
  • flattens outliers in all channels at once
Cons
  • fusing the rotation may need architectural changes
  • even then, it breaks the tying of embedding and lm_head (+156M on 0.6B)
  • online rotation adds Hadamard transforms at inference
Sink Spreading
moves only the one outlier direction, inside the weights
Pros
  • no runtime change, a standard checkpoint
  • tying kept, only 152 of 311 tensors change
  • also removes the mid-text outlier (A10 PPL 33.6)
Cons
  • approximate: float PPL +0.2, some loss on generation tasks
  • 8 bits still weaker than a prefix (A8 PPL 5,723)
  • the outlier moves into the weights (max 0.42 → 23.8)
